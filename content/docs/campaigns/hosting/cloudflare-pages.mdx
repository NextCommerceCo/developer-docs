---
title: Deploy a campaign to Cloudflare Pages
description: Connect a Page Kit repository, verify a branch preview and configure a campaign domain on Cloudflare Pages.
audience: [developer]
---

Cloudflare recommends Workers for new projects. A Worker can serve the Page Kit build as static assets. Use the steps below when your team has chosen Pages. See [Cloudflare’s platform guidance](https://developers.cloudflare.com/pages/get-started/) and [Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/).

## Connect the repository

1. Open **Workers & Pages** in the Cloudflare dashboard and select **Create application**. Choose **Pages**.
2. Choose the Git import option. Cloudflare’s [static HTML guide](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/) calls it **Import an existing Git repository**. Its [Git integration guide](https://developers.cloudflare.com/pages/get-started/git-integration/) calls it **Connect to Git**.
3. Authorize access to the campaign repository, select it and choose **Begin setup**.
4. Select your production branch. For a standard Page Kit project, leave the framework preset unset, enter `npm run build` under **Build command** and `_site` under **Build output directory**. The root directory defaults to the repository root. For a nested project, set **Root directory (advanced) → Path** to the folder containing the build’s `package.json`. Match the Node version used locally.
5. Choose **Save and Deploy**. After the build succeeds, open the assigned `pages.dev` hostname at the campaign’s landing path.

## Review a branch preview

Push a branch and open its preview deployment. For repeat QA use the branch alias shown by Pages. Copy the hostname and complete the [preview checks](/docs/campaigns/hosting#verify-the-preview). Record the commit and tested campaign URL for the person approving release.

## Connect the live hostname

Under **Custom domains**, add the campaign subdomain first. Follow the DNS instructions for that hostname and wait for activation.

Commit `_redirects` in the build directory. After `npm run build`, have the host run `cp _redirects _site/_redirects` so each deployment includes the rules. For a campaign subdomain whose root should send visitors to the storefront, use the rule `/ https://shop.example.com/ 301`, replacing the destination. Keep campaign paths outside that rule.

## Release and rollback

Merging to the configured production branch publishes the new build. Follow the [launch checks](/docs/campaigns/hosting#launch-and-recover) before directing ads to it. In Deployments, select the known-good production deployment and roll back to it.

See the [Cloudflare Pages deployment documentation](https://developers.cloudflare.com/pages/configuration/preview-deployments/).
