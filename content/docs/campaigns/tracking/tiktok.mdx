## What it does

The TikTok adapter loads TikTok's pixel with your pixel ID on every funnel page and sends the SDK's funnel events to it as TikTok standard events. It covers presell, landing, checkout, upsell and receipt pages. It runs in the browser only.

NEXT does not send TikTok events from the server. The **TikTok Pixel Events** store app does not help here either: it loads on your NEXT storefront only, runs in the browser only, and does not reach campaign funnels.

## Before you start

- A TikTok pixel. Copy its pixel ID from TikTok Events Manager, under **Data sources**.
- A funnel built from a starter template. The adapter ships with every template family except `landing`.
- Your funnel domain added in the Campaigns app under **Settings**, then **Allowed Domains**, as a **Production** domain.
- If you plan to turn on advanced matching, check that your privacy policy and consent handling cover sending the shopper's email and phone to TikTok. See [Privacy and consent](/docs/campaigns/tracking#privacy-and-consent).

## Set up

2. Add your pixel ID:

{
  "my-campaign": {
    "name": "My Campaign",
    "tiktok_pixel_id": "CXXXXXXXXXXXXXXXXXXX"
  }

3. Optional: add `"tiktok_advanced_matching_enabled": "true"` to send the shopper's email and phone to TikTok. The adapter also accepts `"1"` and `"yes"`.

## Events sent

The pixel sends a page view with `ttq.page()` on every page load. On top of that, the adapter forwards these SDK events by default:

| SDK event | TikTok event | When it fires |
| --- | --- | --- |
| `dl_view_item` | `ViewContent` | A page shows a package |
| `dl_add_to_cart` | `AddToCart` | An item is added to the cart |
| `dl_begin_checkout` | `InitiateCheckout` | The checkout form loads |
| `dl_add_payment_info` | `AddPaymentInfo` | Payment details are complete |
| `dl_purchase` | `Purchase` | The first page after payment |
| `dl_upsell_purchase` | `Purchase` | The page after an upsell is accepted |

Each event is sent with `ttq.track(name, properties, { event_id })`. A checkout that opens with a package already selected sends no `AddToCart`, because the SDK emits no `dl_add_to_cart` for it.

To send fewer events, add `tiktok_blocked_events` with a comma-separated list, for example `"tiktok_blocked_events": "dl_add_payment_info"`. You can use `dl_*` names or TikTok names. A TikTok name matches every SDK event mapped to it, so blocking `Purchase` blocks both the order and the upsell purchase. To send more, list them in `tiktok_allowed_events`, or use `"all"` to send every event the adapter can map, which adds `Search` (`dl_view_search_results`), `CompleteRegistration` (`dl_sign_up`) and `Subscribe` (`dl_subscribe`). A list in `tiktok_allowed_events` replaces the default set rather than adding to it.

### Advanced matching

With `tiktok_advanced_matching_enabled` on, the adapter calls `ttq.identify` with the shopper's email and `phone_number`. It does this only when the SDK creates the prospect cart, which happens once per session when the checkout has a valid email or phone, a first and last name, and items in the cart. It does not fire as the shopper types.

| Detail | Behaviour |
| --- | --- |
| Values sent | The raw email, and the phone in E.164 format (`+` and country code). A phone without a country code is not sent |
| Marketing checkbox | If the checkout has an accepts-marketing checkbox and it is unchecked, nothing is sent. If the page has no such checkbox, the call is not blocked |

## Attribution requirements

TikTok's click ID is the `ttclid` parameter on your ad's landing URL. Keep it there, and do not strip query strings on your landing pages. In the test order, TikTok's own pixel read `ttclid` from the landing URL and stored it in a first-party cookie, so TikTok can still read the click ID on later pages. Keep every funnel page on the same domain, or on subdomains of one domain, so that cookie is available on the checkout, upsell and receipt pages.

The NEXT order is a separate matter. SDK 0.4.43 does not store `ttclid` in the order's attribution: it carries the parameter from page to page in the URL, but it never saves it. That does not stop the pixel from attributing, but it means you cannot see the TikTok click ID on the order, export it, or send it from a server of your own. SDK 0.5.0 stores `ttclid` in the order's attribution metadata by itself (from the 0.5.0 source; not tested).

### Keep ttclid on the order with SDK 0.4.x

On SDK 0.4.x you can copy the click ID into the order's attribution metadata yourself with `next.addMetadata`. Add this script to every funnel page, for example in each page layout under `_layouts/`, after the SDK loader:

```html title="_layouts/base.html"
<script>
  window.nextReady = window.nextReady || [];
  window.nextReady.push(function (sdk) {
    var ttclid = new URLSearchParams(window.location.search).get('ttclid');
    if (ttclid) {
      sdk.addMetadata('ttclid', ttclid);
    }
  });
</script>
```

Run it on the checkout page as well as the landing page. The checkout re-reads attribution when it loads, and the order is created from that page. This snippet was not run in NEXT's test order, so check it before you rely on it: on the checkout page, `next.getAttribution().metadata.ttclid` should show the value, and the order's attribution metadata should carry it. On a Shop Sync store you can then copy it to a Shopify order metafield the same way as the other click IDs in the [Shop Sync metadata guide](https://guides.nextcommerce.com/guides/shop-sync-metadata).

## Purchases, revenue and upsells

| Field | Order purchase | Upsell |
| --- | --- | --- |
| TikTok event | `Purchase` | `Purchase` |
| `event_id` | The NEXT order number, for example `100041` | The order reference plus `-US1`, `-US2` and so on |
| `value` | Item revenue, excluding shipping and, on tax-exclusive stores, tax | The upsell line only |
| `currency` | The order currency | The order currency |

The order purchase also carries `content_type: 'product'`, a `contents` list (`content_id`, `content_name`, `content_category`, `brand`, `price`, `quantity`) and `query` set to the coupon code when one was used.

TikTok has no separate upsell event in this adapter. Each accepted upsell arrives as another `Purchase` with its own event ID, so TikTok's purchase count includes upsells: an order with two accepted upsells counts as three purchases. If you want TikTok to count one purchase per order, add `"tiktok_blocked_events": "dl_upsell_purchase"`. Upsell revenue then does not reach TikTok.

## Browser and server events

TikTok receives browser events only. No NEXT app sends TikTok events from the server for campaign orders: the **TikTok Pixel Events** store app is storefront-only and browser-only, and NEXT has no TikTok Events API sender. There is nothing to deduplicate, so the only duplicate risk is a second TikTok pixel on the same pages.

TikTok should receive each purchase once, from one sender, and for a NEXT funnel that sender is the funnel pixel unless you deliberately add another. See [Send each purchase from one place](/docs/campaigns/tracking#send-each-purchase-from-one-place).

### If you add your own Events API sender

TikTok deduplicates a pixel event and an Events API event only when both carry the same event name and the same `event_id`, within 48 hours of the first. It keeps the first one it receives. Deduplication is not needed when the pixel and the Events API send different events. See [TikTok event deduplication](https://ads.tiktok.com/resources/help/article/event-deduplication?lang=en).

So a server `Purchase` you send yourself must use the same `event_id` as the pixel:

- Order purchase: the NEXT order number, for example `100041`.
- Upsell purchase: the order reference plus `-US1`, `-US2` and so on.

The adapter passes the SDK's `event_id` for every event. A code comment in the adapter says purchases use `transaction_id`; in practice they are the same value, because the SDK sets a purchase's `event_id` to its `transaction_id`, and the test order showed both as the order number. Non-purchase events get a random `event_id` generated in the browser, so a server cannot reproduce it. Send only `Purchase` from the server, or block the matching browser events.

The TikTok Pixel Events store app uses a different purchase ID format on the storefront: your store subdomain, a hyphen and the order number, for example `your-store-100041`. That format does not apply to funnels, and the funnel adapter does not use it.

### Shop Sync stores

NEXT has not confirmed whether TikTok's Shopify integration reports orders that Shop Sync pushes into Shopify. Those orders are tagged `NEXT` and carry no UTM parameters or click IDs unless you map them. If your Shopify-side TikTok setup does report them, TikTok can get each purchase twice: once from the funnel pixel and once from Shopify. Pick one sender. See [Tracking on Shop Sync stores](/docs/campaigns/tracking/shop-sync).

## Worked example

A campaign that sends TikTok with advanced matching on, counts one purchase per order, and keeps the TikTok click ID on the order with the snippet from [Attribution requirements](#attribution-requirements):

```json title="_data/campaigns.json"
{
  "summer-offer": {
    "name": "Summer Offer",
    "sdk_version": "0.4.43",
    "tiktok_pixel_id": "CXXXXXXXXXXXXXXXXXXX",
    "tiktok_advanced_matching_enabled": "true",
    "tiktok_blocked_events": "dl_upsell_purchase"
  }
}
```

With this setup, a shopper who clicks a TikTok ad, buys one package and accepts one upsell sends: page views on every page, `ViewContent` where a package is shown, `InitiateCheckout` when the checkout loads, one `identify` call when the prospect cart is created (if the marketing checkbox allows it), `AddPaymentInfo`, and one `Purchase` with the order number as `event_id` on the first page after payment. No `Purchase` is sent for the upsell.

## Verify it works

1. Open a funnel page on your production domain with `?ttclid=test&nfdebug=true` added to the URL. Do not add `?ignore=true`, which turns all tracking off for the browser tab.
2. In the browser console, run `NextForwarder.getStatus()`. The `tiktok` entry should show `active: true`, and `sent` should increase as you move through the funnel.
3. In the browser's network panel, filter for `analytics.tiktok.com`. You should see pixel requests on every page.
4. Place a test order with a [test card](/docs/testing). On the upsell or receipt page the TikTok entry's `sent` count should include the `Purchase`. Accept an upsell and you should see another `Purchase` on the next page, unless you blocked `dl_upsell_purchase`.
5. If you added the `ttclid` snippet, run `next.getAttribution().metadata.ttclid` on the checkout page before you pay. It should return `test`.
6. In TikTok Events Manager, check that the events arrive for your pixel. NEXT has not checked this step.

<Callout type="warn" title="Test orders reach your pixel">
The adapter does not skip test orders. A test-card order that reaches the upsell or receipt page sends a real `Purchase` to the pixel ID in your campaign. Place test orders before you switch to your live pixel ID, or expect them in your TikTok reports.
</Callout>

More checks are in [Test and troubleshoot tracking](/docs/campaigns/tracking/testing-and-troubleshooting).

## Troubleshooting and limits

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| No TikTok requests at all | Built with `npm run dev`, `tiktok_pixel_id` empty, or `?ignore=true` set earlier in the tab | Build with `npm run build`; check the key; open a new tab without `?ignore=true` |
| Every event counted twice | TikTok also loaded by GTM or a page script | Remove the other TikTok pixel |
| More purchases in TikTok than orders | Accepted upsells are sent as extra `Purchase` events | Expected; block `dl_upsell_purchase` if you want one purchase per order |
| No `AddToCart` | The checkout opened with a package already selected | Expected; the SDK sends no add-to-cart event for a preselected package |
| No `identify` call | Advanced matching is off, the marketing checkbox is unchecked, or the prospect cart was never created (missing name, email or phone, or empty cart) | Check the key and the checkout fields |
| No `Purchase` after a test order | The shopper never reached a page after payment, or the order was already reported in that browser | Load the upsell or receipt page; use a fresh browser profile for each test |
| `ttclid` missing on the NEXT order | SDK 0.4.x does not store it | Add the `ttclid` snippet, or move to SDK 0.5.0 |

- TikTok receives no event for subscription renewals or other orders created without a funnel visit.
- Accepting an upsell bundle of several items through the accept-upsell button sends one upsell event per item, each valued at the whole bundle total (SDK 0.4.43 source). On TikTok that becomes several `Purchase` events with inflated revenue. Block `dl_upsell_purchase` if your funnel offers bundles as upsells.
- The **TikTok Pixel Events** store app does not load on campaign funnels and has no setting to skip test orders. Do not rely on it for funnel tracking.
- On SDK 0.5.0, `ttclid` reaches the order and the `dl_*` events, but not the SDK's own tracking-event attribution (from the 0.5.0 source; not tested).
